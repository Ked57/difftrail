# Vue single-file component dependency extraction

Research date: 2026-10-15. Evidence for [Verify Vue single-file component extraction and dependency gaps](https://github.com/Ked57/difftrail/issues/11), supporting [Choose graph acquisition and the supported resolution boundary](https://github.com/Ked57/difftrail/issues/5).

## Scope and conclusion

Vue support is mandatory for Difftrail's first version. This note verifies extraction facts, not the human's remaining support or safety policies. It is source/documentation inspection only: no packages were installed, no fixtures executed, and no production behavior changed. Dependency-cruiser source links pin `c580daf6477aa5619bacad9c9091c9b7cc81882d` (declared version 18.6.0). Vue documentation links pin `40aa88af0094f7bab4aaf786e55c748a6a251d88`. [Dependency-cruiser metadata](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/meta.cjs)

**Finding:** dependency-cruiser has a concrete Vue script-import extraction path, including ordinary script and script setup blocks. Its built-in Vue wrapper does not extract external block `src` references or template/style relationships. Therefore its Vue capability alone does not establish complete SFC dependency coverage. This conclusion follows from the implementation described below; actual supported combinations still require runtime acceptance fixtures.

## Verified source behavior

### Vue graph nodes and extraction prerequisites

The available-extension registry includes `.vue` when either a supported `vue-template-compiler` or `@vue/compiler-sfc` is available. Directory discovery uses the scannable-extension registry. An explicit file input bypasses that directory extension check, so merely passing a `.vue` path is not evidence that a compiler is usable. Default resolver extensions use the same scannable list; `.vue` can consequently be resolved and followed with a usable compiler and matching resolver settings. Explicit resolver extension overrides can change that behavior. [Availability registry](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/meta.mjs), [Entry discovery](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/gather-initial-sources.mjs), [Resolver defaults](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/main/resolve-options/normalize.mjs), [Followability](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/resolve/module-classifiers.mjs)

Compiler selection tries `vue-template-compiler` first, then `@vue/compiler-sfc` when that fails. Supported ranges in the pinned metadata are Vue2 compiler `>=2.0.0 <3.0.0`, Vue3 compiler `>=3.0.0 <4.0.0`, and TypeScript `>=2.0.0 <7.0.0`. These broad version ranges do not promise that every historical compiler understands modern script setup or type syntax. [Vue wrapper](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/vue-template-wrap.cjs), [Version metadata](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/meta.cjs)

The wrapper's `require` helper resolves compiler packages using its own Node module environment, checks the package version, and catches loading/version failures as `false`. It does not discover a compiler independently for each analyzed snapshot/package. Dependency-cruiser's FAQ consequently instructs installing compilers where dependency-cruiser can resolve them. Vue itself includes its SFC compiler and recommends the `vue/compiler-sfc` deep import, whereas this dependency-cruiser wrapper requests `@vue/compiler-sfc` directly. **Inference:** a target project's Vue installation, especially with isolated package layouts, does not by itself prove Difftrail's extractor can load that compiler. Mandatory Vue support needs an explicit, verified compiler availability strategy; this research does not choose packaging or auto-install behavior. [Load helper](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/utl/try-require.cjs), [FAQ](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/doc/faq.md), [Vue tooling documentation](https://github.com/vuejs/docs/blob/40aa88af0094f7bab4aaf786e55c748a6a251d88/src/guide/scaling-up/tooling.md#lower-level-packages)

### Script and script setup import edges

For Vue3 the wrapper calls `parse`, reads `descriptor.script.content` and `descriptor.scriptSetup.content`, and concatenates both when present. For Vue2 it calls `parseComponent` and reads analogous fields; that code path alone does not establish modern Vue2 script setup compatibility. It does not call `compileScript`, compile templates, interpret macros, or honor block-language preprocessors. The Vue3 upstream wrapper tests cover ordinary script, script setup, combined blocks, scriptless files, and invalid SFCs; these tests were read, not run. [Wrapper](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/vue-template-wrap.cjs), [Vue3 wrapper tests](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/test/extract/transpile/vue3-template-wrap.spec.mjs)

`.vue` is considered TypeScript-compatible. Setting `tsPreCompilationDeps: true` (or selecting `parser: "tsc"`) uses the TypeScript extractor **if a usable TypeScript compiler is available**. That parser first strips the SFC down to the script contents through the Vue wrapper, then builds a TypeScript AST. The extractor recognizes ordinary imports, re-exports, type-only imports/exports, literal CommonJS requires, and literal dynamic imports, including template literals without substitutions. This supplies a source-supported path for both JavaScript and TypeScript script blocks, preserving type dependencies rather than depending on JavaScript parsing of TS syntax. `tsPreCompilationDeps: "specify"` additionally compares against the Acorn result to classify pre-compilation-only edges. [Parser selection](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/tsc/extract.mjs), [Compatible extensions](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/helpers.mjs), [SFC-to-TS AST](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/tsc/parse.mjs), [TS dependency extraction](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/tsc/extract-typescript-deps.mjs), [Extraction pipeline](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/extract-dependencies.mjs)

Upstream expected graph fixtures include `.vue` importing another `.vue`, and a `lang="ts"` component importing JS, TS and a type-only dependency. They are useful precedent, not executed Difftrail acceptance evidence. [Vue application fixture](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/test/main/__fixtures__/cruise-reporterless/vue.json), [TS component input](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/test/extract/__mocks__/vue/vue.vue), [Expected dependencies](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/test/extract/__fixtures__/vue.json)

### Missing relationships and silent omissions

- **External blocks:** Vue permits `src` references on language blocks, including external script/template/style and custom blocks. The reviewed wrapper reads inline script content only, never block `src` attributes; it therefore does not create those SFC-to-external-file edges. Supporting them would require additional extraction beyond this wrapper. [Vue SFC specification](https://github.com/vuejs/docs/blob/40aa88af0094f7bab4aaf786e55c748a6a251d88/src/api/sfc-spec.md#src-imports), [Wrapper](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/vue-template-wrap.cjs)
- **Templates/styles/custom blocks:** their contents are not fed into dependency extraction. Template assets, stylesheet imports/URLs, and build-plugin-generated custom-block imports consequently are not covered by the script extraction path. Changing the `.vue` file still makes it a changed seed; the gap concerns changes to referenced external files reaching that component. This distinction follows from Difftrail's accepted file-level rule and the wrapper mechanics. [Wrapper](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/vue-template-wrap.cjs), [Vue custom-block tooling](https://github.com/vuejs/docs/blob/40aa88af0094f7bab4aaf786e55c748a6a251d88/src/guide/scaling-up/tooling.md#sfc-custom-block-integrations)
- **Implicit components:** locally imported components have explicit script edges. Global registration makes components usable without imports in each consumer; raw script extraction does not connect each template consumer to that global component. The same limitation applies to tooling conventions that inject imports rather than storing them in source. No plugin execution or global-registration inference was verified here. [Vue registration](https://github.com/vuejs/docs/blob/40aa88af0094f7bab4aaf786e55c748a6a251d88/src/guide/components/registration.md), [Wrapper](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/vue-template-wrap.cjs)
- **Invalid SFC:** Vue3 `parse` errors cause the wrapper to return an empty string, without forwarding the errors into structured graph diagnostics. This is explicitly tested upstream. A scriptless component returns the same empty text. **Inference:** graph output alone cannot distinguish these cases; mandatory support needs separate validation if Difftrail must diagnose invalid SFCs. [Wrapper and error branch](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/vue-template-wrap.cjs), [Invalid-SFC test](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/test/extract/transpile/vue3-template-wrap.spec.mjs)
- **Compiler/parser fallback:** when no matching wrapper is available the transpile dispatcher returns original source. TypeScript extraction is conditional on availability; otherwise selection can fall back to Acorn, whose strict parse failures fall back to `acorn-loose` without a structured warning. Successful output thus is not a completeness certificate. Variable/expression imports likewise are not represented as unknown edges by the reviewed literal-import extraction. [Dispatcher](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/transpile/index.mjs), [Selection](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/extract-dependencies.mjs), [Acorn fallback](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/acorn/parse.mjs), [Literal import handling](https://github.com/sverweij/dependency-cruiser/blob/c580daf6477aa5619bacad9c9091c9b7cc81882d/src/extract/tsc/extract-typescript-deps.mjs)

## Remaining acceptance evidence and human decisions

Required future fixtures should cover `.vue` as both entry and target; normal/script setup/combined blocks in JS and TS; type-only and literal dynamic imports; scriptless components; invalid SFC diagnostics; compiler absence/incompatible version; resolver extension overrides; per-package aliases; and old/new isolated snapshots. External block references, implicit registration, and template/style inputs need tests matching the support policy chosen by the human. No claim that those fixtures pass is made here.

During this investigation, the human confirmed required Vue support includes normal/script setup JS/TS imports **and explicit script/template/style `src` references**. The latter therefore require supplemental SFC extraction; they cannot be delegated solely to dependency-cruiser's reviewed wrapper. The parent graph-design ticket records the decision and any diagnostic requirements. This research does not independently choose Vue2 versus Vue3 product support, compiler distribution, non-import relationship policy, or fail/warn/expand behavior.

Dependency-cruiser availability and extension filtering must not become automatic directory/file-kind ignores: Difftrail's agreed inventory and changed seeds remain governed by Gitignore, with tracked files eligible. Historical resolution constraints from the earlier graph research still apply. This documentation-only artifact has no changed browser/app/API/CLI surface; runtime manual QA does not apply.
